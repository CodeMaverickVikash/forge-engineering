# FORGE: an autonomous software engineering organization behind one command

```
/forge Build a complete notification system.
/forge Fix the payment issue.
/forge Make this application production-ready.
```

FORGE turns a one-line request into finished, verified engineering work. It explores your codebase, rewrites the request as a grounded specification, assembles the smallest team of specialist agents that covers the task's risks, then implements, tests, browser-verifies, reviews and reports. **It never commits, pushes or opens pull requests.** Every change is left uncommitted for you to review.

It runs on **Claude Code** and **Google Antigravity** from one shared core.

| | |
|---|---|
| **Entry point** | `/forge <request>` (the only user-facing command) |
| **Specialists** | 26 subagents in 5 divisions: product, architecture & engineering, quality, delivery, intelligence ([docs/agents.md](docs/agents.md)) |
| **Skills** | 27 reusable, technology-independent skills with per-stack references ([docs/skills.md](docs/skills.md)) |
| **Stacks** | Any stack, discovered from evidence. The registry ships 116 technology signatures plus references for Node, Python, Java/Spring, Go, PHP/Laravel, .NET, Ruby/Rails, Rust, React/Next, Vue, Angular, Svelte, React Native/Expo, Flutter, Android and iOS |
| **Skill discovery** | Free & open-source only, license-verified per skill, with the Vercel Skills CLI as the primary engine. **Nothing is installed without your explicit approval** ([docs/skill-discovery.md](docs/skill-discovery.md)) |
| **Browser QA** | Playwright journeys + Chrome DevTools MCP (console, network, performance) with a hard completion gate |
| **Runtime deps** | None. Node ≥ 18 is optional and powers the fast stack detector, with a manual fallback |

## Install

```bash
git clone <this-repo> forge-engineering && cd forge-engineering
./scripts/install.sh                 # macOS / Linux / Git Bash. Auto-detects Claude Code and Antigravity
.\scripts\install.ps1                # Windows PowerShell
```

The options are `--target claude|antigravity|all`, `--scope user|project`, `--project <dir>`, `--dry-run`, `--force` and `--uninstall` (PowerShell: `-Target`, `-Scope`, `-Project`, `-DryRun`, `-Force`, `-Uninstall`). Restart your session, then run `/forge`. Details, plugin-marketplace installs and MCP setup are in [docs/installation.md](docs/installation.md).

**Recommended for web apps:** connect the browser-QA MCP servers:
```bash
claude mcp add chrome-devtools -- npx -y chrome-devtools-mcp@latest
claude mcp add playwright -- npx @playwright/mcp@latest
```

## How it works

```
/forge "<request>"
  │  1 UNDERSTAND   classify type, size (Q/S/M/L) and risk
  │  2 EXPLORE      detect-stack.mjs → .forge/context.json, then targeted reading
  │  3 SPECIFY      prompt-enhancement → .forge/tasks/<slug>/spec.md (single source of truth)
  │  4 ARCHITECT    routing matrix → smallest specialist team, ADR for large tasks
  │  5 PLAN         ordered tasks with file ownership and a validation strategy
  │  6 IMPLEMENT    parallel specialists on disjoint files (native subagents)
  │  7 VERIFY       quality gates G1–G15: tests, types, lint, build, security, Playwright + DevTools
  │  8 FIX          root-cause fixes, at most 3 cycles, nothing hidden
  │  9 REVIEW       independent code reviewer against the spec, plus a scope check
  └ 10 REPORT       FORGE Execution Report, saying what really ran and what didn't
```

**Reviews** (*"/forge Review my current branch"*, *"/forge Review this PR: <url>"*) take a read-only path. FORGE detects the target and base branch, sends one wave of reviewers chosen from the changed areas, and returns a 13-section Engineering Review Report with a status, findings, ticket drafts and a verdict. See [docs/usage.md](docs/usage.md#reviewing-a-pr-or-branch).

Phases scale with the task. A one-line bug fix skips the written spec and plan, but never the detector run, a regression test, browser QA or the independent review; a new subsystem gets the full process. Tasks touching auth, payments, PII, migrations or a public API contract are sized up one step. Read [docs/architecture.md](docs/architecture.md) for the design and [docs/usage.md](docs/usage.md) for examples.

## Models per task

FORGE runs each specialist on the model that fits its job. **Your main model** is the model selected in your Claude Code session (`model: inherit`). The `/forge` orchestrator itself always runs on your main model.

### On your main model (13 agents): they write or verify code, where accuracy matters most

| Agent | What it does | Max turns |
|---|---|---|
| `forge-ai-engineer` | Builds LLM features (prompts, RAG, tools, evals) safely and cost-aware. | 60 |
| `forge-backend-engineer` | Services, endpoints, jobs and CLIs in any stack, with tests. | 60 |
| `forge-database-engineer` | Schemas, safe migrations, indexes and queries, SQL or NoSQL. | 60 |
| `forge-devops-engineer` | Docker, CI/CD, Kubernetes and IaC config; validates locally, never deploys. | 60 |
| `forge-frontend-engineer` | Web UI in any framework, with states, a11y and XSS safety. | 60 |
| `forge-integration-engineer` | REST, GraphQL and gRPC contracts, webhooks, OAuth/OIDC, payments. | 60 |
| `forge-mobile-engineer` | React Native/Expo, Flutter, Android and iOS features, with tests. | 60 |
| `forge-test-automation-engineer` | Deterministic unit, integration, E2E and regression tests; flake triage. | 60 |
| `forge-browser-qa` | Verifies web changes in a real browser via Playwright and Chrome DevTools MCP. | 45 |

### Which models a task uses

| Task | Agents and models |
|---|---|
| Question about the code ("how does X work?") | No agents. The orchestrator answers directly on your main model, with `file:line` evidence |
| Bug fix (size S) | Browser QA and code reviewer on your main model |
| New feature (size M/L) | Engineers, browser QA and code reviewer on your main model. Product manager, QA lead or UX designer on Sonnet when the task needs them |
| Analysis or audit | Architect and security engineer on your main model. Project explorer or QA lead on Sonnet when the codebase needs them |

Notes:
- **Max turns** is a cap that stops a runaway agent. It is set well above what real runs need, and an agent that hits it is reported as partial, never as done.
- **Antigravity:** all agents use `inherit`, because Antigravity accepts only `inherit`, `flash` or `pro`. The Sonnet split applies to Claude Code only.
- **To change a model**, edit the `model:` line in `agents/<name>.md` (`inherit`, `sonnet`, `opus`, `haiku`, `fable` or a full model ID). Then run `node scripts/build.mjs` and reinstall with `scripts/install.sh --target claude` (or `install.ps1`). This table regenerates itself.
- The full agent catalog, with access level and preloaded skills, is in [docs/agents.md](docs/agents.md).

## Guarantees and limits

- **Honest verification.** Every gate is reported as `PASSED`, `FAILED`, `PRE-EXISTING`, `NOT RUN`, `UNAVAILABLE` or `N/A`, with evidence. A missing Chrome DevTools MCP connection makes a change *"implemented, not browser-verified"*. It never counts as a pass.
- **Safe autonomy.** FORGE edits code and runs local tools on its own. Commits, pushes, PRs, deploys, destructive data operations, new dependencies and paid services are out of bounds without your authorization. In Claude Code the git rules are **enforced by a hook**: the FORGE git guard blocks `git commit/push/merge/rebase/reset --hard`, `gh pr create` and similar commands from FORGE agents and during `/forge` turns, and leaves your own sessions alone. See [docs/security.md](docs/security.md).
- **Platform differences.** Claude Code and the Antigravity App and CLI run specialists as native subagents. Surfaces without custom subagents (the Antigravity IDE is not documented to support them) fall back to sequential role emulation, and the report says so. See [docs/compatibility.md](docs/compatibility.md).
